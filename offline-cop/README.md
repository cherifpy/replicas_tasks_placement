# Offline COP (Choco-solver + LNS)

Implementation of the paper's **Offline COP** approach (Section 4.1): a constraint
programming model (Choco-solver) + Large Neighborhood Search (LNS), which recomputes a
complete plan (transfers + tasks) over the ENTIRE horizon in a single resolution,
minimizing the sum of flow times (`objectives[0]`).

Copied from `Flowtime 2/src/SchedulingWithDiffN.java` (separate Java project), adapted so
this artifact stays self-contained: see the header of `src/SchedulingWithDiffN.java` for
the details of what changed (a configurable output path instead of a hardcoded absolute
path, metrics exposed in `SchedulingResult` instead of being only printed). The
modeling/search logic itself (constraints, LNS, neighborhoods) is unchanged.

**Model scope**: as with the Heuristic (`../run_heuristic.py`), the traces used here
(`../traces/`, generated by `../generate_traces.py`) have an unlimited
`storage_capacity` - the paper does not model a storage constraint. The Choco model's
storage `cumulative` constraint (`model.cumulative(storageTasks[j], storageHeights[j],
model.intVar(storage_capacity[j]))`) stays in the code (faithful to the original) but is
never binding with a capacity this large.

## Contents

- `src/SchedulingWithDiffN.java` - the model (constraints + LNS), see its header.
- `src/RunOfflineCOP.java` - runner: loads an instance (`infrastructure.csv` +
  `jobs.json`, same format as `../generate_traces.py`), calls
  `SchedulingWithDiffN.runScheduler`, reports `avg_flow_time_s`, `max_flow_time_s`,
  `nb_transfers`, etc.
- `lib/` - vendored jars (Choco-solver 5.0.0-beta.2 "light", org.json) - no Maven Central
  dependency needed to compile/run.
- `out/`, `results/` - created by compilation/execution, regenerable.

**Prerequisites**: JDK 17 or later (LTS recommended: 17, 21 or 25 - tested with JDK
25.0.1). Choco-solver 5 targets Java 17+; no other dependency (Maven/Gradle) is needed,
the jars are already vendored in `lib/`.

**Choco-solver documentation** (to understand/modify `SchedulingWithDiffN.java`):
- Official site: https://choco-solver.org/
- User guide: https://choco-solver.org/docs/
- Javadoc for the version used here (5.0.0-beta.2): https://javadoc.io/doc/org.choco-solver/choco-solver/5.0.0-beta.2/index.html
- Source repository: https://github.com/chocoteam/choco-solver

The Choco classes most relevant to reading this model: `Model`/`Solver` (base API),
`Task`/`IntVar`/`BoolVar` (variables), `model.cumulative(...)` (storage/bandwidth
constraints), and the `org.chocosolver.solver.search.loop.lns.neighbors` package (the 7
LNS neighborhoods, see `getNeighbor1`...`getNeighbor4bis`).

## Usage

```bash
cd simulator/paper-artifact/offline-cop

# 1. Compile
javac -cp "lib/*" -d out src/*.java

# 2. Run Offline COP on an instance generated by ../generate_traces.py
java -cp "out:lib/*" RunOfflineCOP ../traces/inst-10J-50N results/inst-10J-50N

# Solver time budget (see OFFLINE_COP_TIME_LIMIT below)
OFFLINE_COP_TIME_LIMIT=300s java -cp "out:lib/*" RunOfflineCOP ../traces/inst-10J-50N
```

`OFFLINE_COP_TIME_LIMIT` (environment variable, Choco format: `"150s"`, `"5m"`...,
default `"150s"`): time budget for the solver - the problem is NP-hard, this limit is
what makes larger instances practical. The last solution found before expiry is the one
reported; `proven_optimal` in the output indicates whether it was also proven optimal or
just the best one found within the time budget.

`RunOfflineCOP`'s second argument (optional) is an output directory: if given,
`works_exec_solution.csv`/`transfers_solution.csv` are written there on every improved
solution found; if omitted, only the final summary is printed.

Output (example, `inst-10J-50N`, `OFFLINE_COP_TIME_LIMIT=150s`):

```
            instance: inst-10J-50N
             nb_jobs: 10
      found_solution: true
      proven_optimal: false
       sum_flow_time: ...
     avg_flow_time_s: ...
     max_flow_time_s: ...
        nb_transfers: ...
        solve_time_s: ...
         wall_time_s: ...
  nb_solutions_found: ...
```

`avg_flow_time_s` (= `sum_flow_time / nb_jobs`) is directly comparable to the metric of
the same name reported by `../run_heuristic.py` (Heuristic) and
`../online-cop/run_online_cop.py` (Online COP), on the same instance.

## Correspondence with the paper

| Paper concept | File / function |
|---|---|
| Offline COP model (Section 4.1), sum-of-flow-times objective | `src/SchedulingWithDiffN.java` -> `runScheduler` (`objectives[0]` = sum flow time, `objectives[1]` = max flow time) |
| Large Neighborhood Search (7 combined neighborhoods) | `src/SchedulingWithDiffN.java` -> `getNeighbor1`...`getNeighbor4bis`, `setLNS`/`MyMoveLNS.java` |
| Bandwidth-sharing constraint (1 active transfer per node) | `src/SchedulingWithDiffN.java` -> `ENABLE_BANDWIDTH_SHARING_CONSTRAINT`, `model.cumulative(tasksForNode, heightsForNode, model.intVar(1))` |
